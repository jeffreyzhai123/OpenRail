# Plan: V1 frontend (`frontend/`) — what's still needed

## Context

The backend is done. `sim-core` (engine, fault injection, ledger + 7 invariants,
naive/hardened handlers, shrink, sweep) and `sim-scenarios` (3 scenarios,
including ACH, `decisions-log.md` D2) all pass `cargo test`/`clippy`/`fmt`.
`sim-api` (`sim-api-plan.md`, API1–API7) is fully built: every route, the
error envelope, replay encoding, and the golden fixtures this plan's frontend
work builds against (`frontend/src/api/fixtures/*.json`, generated by
`crates/sim-api/tests/fixtures.rs`, `UPDATE_FIXTURES=1`).

The frontend itself is at **step 0 only**: Vite/React/TS scaffold, tooling
(`eslint`, `prettier`, `vitest`), and those generated fixtures. `App.tsx` is
still the original header stub. Steps 1–8 below are what's left. This
supersedes the old `frontend-plan.md` (deleted) — that plan's deviations/asks
to the backend are now all resolved (`decisions-log.md`), so this doc only
covers what remains: the frontend itself.

## Principles (unchanged from the original plan)

- **The frontend displays results. It never decides them.** Invariants,
  shrinking, the replay encoding and fault-plan generation all live
  server-side. The browser holds inputs (scenario, seed, handler, fault plan)
  and renders `RunResponse`s.
- **Minimal dependencies**, matching CLAUDE.md. Runtime deps are `react` and
  `react-dom` only. No router, state library, chart library, CSS framework,
  schema library or compression library.
- **JS has no i64.** Cents, time, seq and event ids are `number`s the decoder
  checks with `Number.isSafeInteger`, rejecting at the boundary otherwise.
  `time` is simulated milliseconds. The seed is a `u32`, so it's a plain
  `number`, checked against `0..=4294967295`. `formatCents` uses `BigInt` and
  never divides as a float.
- **The network boundary handles failures** (`api/client.ts`): timeouts, one
  retry on idempotent calls, response validation, and aborting superseded
  requests so a slow old response can't overwrite a newer one.

## API contract (already live — read it from the source, not this doc)

The contract isn't aspirational anymore; it's shipped. Treat these as the
source of truth, not the TS sketch below:
- `crates/sim-api/src/dto.rs` — every request/response shape.
- `crates/sim-api/src/error.rs` — the error envelope and every error code.
- `crates/sim-api/src/routes/*.rs` — the five routes (`run`, `scenarios`,
  `replay`, `shrink`, `sweep`) plus `GET /health`.
- `frontend/src/api/fixtures/*.json` — real captured responses for all three
  scenarios × both handlers, plus `shrink.json`, `sweep.json`, `replay.json`.

Shape, for reference (mirror this in `types.ts`, but verify against the Rust
types above — they're generated from the same source and will drift less):
```ts
type Cents = number; type EventId = number;                 // safe integers, checked at decode
type CardEvent =
  | { Authorized: { charge_id: number; amount: Cents } }
  | { Captured: { charge_id: number; amount: Cents } }
  | { Refunded: { charge_id: number; amount: Cents } };
type AchReturnCode = "R01" | "R02" | "R03" | "R04" | { Other: string };
type AchEvent =
  | { Initiated: { entry_id: number; amount: Cents } }
  | { Batched: { entry_id: number } } | { Settled: { entry_id: number } }
  | { Returned: { entry_id: number; code: AchReturnCode; amount: Cents } };
type EventKind = { Card: CardEvent } | { Ach: AchEvent };
interface SimEvent { id: EventId; time: number; seq: number; kind: EventKind }
type FaultOp =
  | { Duplicate: { event_id: EventId } } | { Reorder: { event_id: EventId; window: number } }
  | { Delay: { event_id: EventId; by: number } } | { Drop: { event_id: EventId } }
  | { CrashRestart: { at: number } };
interface JournalEntry { source: EventId; intent: string; kind: "Capture" | "Refund";
                         postings: { account: string; delta: Cents }[] }
interface InvariantResult { name: string; passed: boolean; message: string | null }
type Handler = "naive" | "hardened";

GET  /scenarios            -> { id, name, description, accounts: string[], workload: SimEvent[], story_plan: FaultOp[] }[]
POST /run    { scenario_id, seed: number, handler, fault_plan: FaultOp[] | null } -> RunResponse
GET  /replay/:encoded      -> RunResponse
POST /shrink { scenario_id, seed, handler, fault_plan, invariant: string }
             -> { original: FaultOp[]; shrunk: FaultOp[]; invariant; candidates_tried: number; run: RunResponse }
POST /sweep  { scenario_id, seed_start: number, count: number }
             -> { count; naive: { failed: number }; hardened: { failed: number } }
RunResponse = { scenario_id, seed: number, handler, fault_plan: FaultOp[], trace: SimEvent[],
                opening: Record<string, Cents>, journal: JournalEntry[],
                ledger: { accounts: Record<string, Cents> }, invariants: InvariantResult[],
                trace_hash: string, replay: string }
GET  /health               -> { status: "ok" }
Errors: 4xx/5xx with { error: { code: string, message: string } }. Match on `code`, never `message`
        (full table in sim-api-plan.md's "Errors").
```
**Replay link:** `#r=<replay>&h=<trace_hash>` in the URL fragment. On load,
call `GET /replay/:r` and compare the returned `trace_hash` to `h`: **verified
identical**, **determinism break**, or **unverified** (no `h`). An
unsupported encoding version shows a clear message, not a generic error.

## Tests (Vitest, all deterministic: no live network, no wall clock, `fetch` stubbed)

- **decode:** every fixture decodes. Rejected: missing field, unknown
  `EventKind`/`FaultOp` tag, unsafe integer (`2**53`), a seed outside
  `0..=u32::MAX` or a string seed, an `invariants` that isn't an array.
- **client:** timeout aborts and returns a timeout error. One retry on 503,
  then success. No retry on 400, and the error envelope reaches the UI.
  Malformed JSON gives a DecodeError. A superseded request is aborted, so only
  the latest response renders.
- **lib:** `formatCents` matches the Rust `Display` cases in `money.rs` (0, 5,
  -5, 100, -1234, ±2^53−1). `balancesAt` at k=0 equals opening, and a fold
  that disagrees with the final ledger throws. The seed validator rejects
  negatives, non-integers and values above `u32::MAX`. Replay fragments
  round-trip.
- **components** (Testing Library, by behaviour): Run under naive shows
  `single_capture_per_intent` failed, and hardened shows all passed.
  Scrubbing and ←/→ change the balances. Adding a `Duplicate` op sends it in
  the next run request. Picking a scenario loads its `story_plan`. Changing
  the seed resets the plan to `null`. ReplayBadge shows verified / mismatch /
  unverified. ShrinkView never says "minimal". SweepChart renders the
  fixture's rates.
